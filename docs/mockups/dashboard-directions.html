The same Home screen, four ways. Pick the one whose density and structure fit how you work. The data is example state from the real specs, not live.

Every direction shows the same thing: what waits on you first, then the live runs, then idle projects and recently closed. Tap a waiting item to see how you would act on it from that direction. Switch to the phone frame to see the same screen at your phone's width.

What is the same in all four

Five pages, no project switcher. Every list shows all projects and filters by project, phase or kind. The dashboard derives everything from the ledgers, the gate files, the retro files, the deferrals and the PR state. Nothing on it is hand-written.

The loop the dashboard runs

Launch a headless run. The run stops at gate A, at gate B and at retro-ready, and the dashboard shows the questions. You answer, and the dashboard relaunches the run, which continues from the recorded answers. At the end the run opens its PR; the dashboard shows the checks and you merge. Then you start the next spec yourself.

Why stop and relaunch rather than keep a process waiting: a gate can wait for hours, a relaunch is a fresh supervisor that reads the answers from the spec folder, and it survives dashboard restarts. This is a change in the harness, not only the UI: today a headless run records default picks and carries on.

How you get told that something waits

Two facts shape this. The dashboard binds to localhost only, and this machine has no Tailscale. Today your phone cannot reach it at all. Acting from the phone needs a path in, whichever way the notification goes.

A hosted bridge, since you raised it

A small service of your own on the internet could sit between the dashboard and the phone. The dashboard talks out to it; the phone talks to it. It would buy three things: no VPN on the phone, pushes through a server that is always up, and a last-known state you can read when the home machine is rebuilding. It would cost a second deployment to run, a second copy of the state to keep honest, and an authenticated path from the internet to gate answers and PR merges. The harness still runs at home, so an answer given while the home machine is down waits there until it is back.

My pick. Start with direction 1 over Tailscale. It gives one source of truth and no session to babysit, and the reachability work is needed anyway once you act from the phone. Keep the overwatch push running during the switch. Build the bridge only if the VPN step on the phone turns out to annoy you; the dashboard's push module would move there unchanged.
