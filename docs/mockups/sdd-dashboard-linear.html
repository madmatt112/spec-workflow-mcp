Notifications, as decided

You're not acting from the phone, so the box needs no path in. Two channels, both outbound only:

  • Desktop: the open dashboard tab raises an OS notification when a wait appears, so you see it from any window. Click brings the tab forward on the item.
  • Phone: the server posts one line to a push service (Pushover or ntfy, your choice of app) when a wait appears. No reply path; it just says what waits.

Same rule as the overwatch push today: one message per wait, none for progress. The overwatch session stops sending pushes once this is live.

Harness changes this needs

  • A third gates mode next to block and record: the run stops at gate A, gate B and retro-ready, leaves the payload, and exits with a signal the dashboard reads. The dashboard writes the answers and relaunches; the supervisor continues from the recorded answers. Retro and close-out already work this way for headless runs.
  • The supervisor refusal signal from harness-control-pane P4, so a refused launch reads as refused.
  • Per-project merge method and post-merge command in agent-rules.md, so the dashboard merges by each repo's rule and runs the sync-and-build step for this repo.
