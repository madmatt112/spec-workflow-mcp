## Context
Surfaced at the task 19 end-to-end gate (npm test). In a worktree-isolated harness session, SPEC_WORKFLOW_SHARED_ROOT and SPEC_WORKFLOW_WORKSPACE are set in the ambient environment (pointing at the main checkout, not the worktree). Two test files assume a clean environment and fail because of it: src/tools/__tests__/log-implementation.test.ts ('records source "override" when args.projectPath is provided') and src/tools/__tests__/projectPath.test.ts ('log-implementation lets an override displace the context workflow root') — both assert result.success === true and get false, because root-selection's override logic is displaced by the ambient shared-root env var. Reproduced with `env -u SPEC_WORKFLOW_SHARED_ROOT -u SPEC_WORKFLOW_WORKSPACE npx vitest run <those two files>`: both pass clean with the ambient vars unset, and the full suite (141 files, 2272 tests) is fully green the same way. This is the same root-cause family as the already-tracked d-cbcd11d8 (project-manager-durable.test.ts, env-coupled to live dashboard state) but a different pair of files and a different ambient variable; not a regression from any advisor task — these two files have no advisor-spec dependency and fail identically with no advisor code touched at all.

## Decision Deferred
Not fixed under task 19: out of scope for an end-to-end-proof task, and isolating root-selection's tests from the ambient SPEC_WORKFLOW_SHARED_ROOT/WORKSPACE env vars is a test-harness fix, not an advisor-feature change. Left tracked so the gate's true signal isn't lost: `npm test` only reads fully green when these two ambient vars are unset first (as this task's checks-file does).

## Revisit Criteria
When log-implementation.test.ts or projectPath.test.ts is next touched, or when a worktree-isolated session's test-running convention is next revisited (e.g. alongside d-cbcd11d8). A fix likely means the same treatment as d-cbcd11d8: stub or isolate root-selection's env reads in these fixtures rather than relying on the ambient environment being clean.
