## Context
Happened 2026-11-02 16:54Z at run end. Live DB untouched (gate-B annotation). Overwatch had recommended tracking the jobsync store (75d2f99) without checking its worktree setting; jobscout runs worktree "no" safely because it has no remote. tsc/vitest on the pushed main were run by overwatch afterwards. Related: d-e1bae32a (checkpoint on an untracked store).

## Decision Deferred
jobsync's setup has worktree "no", so server-side-match (run-20261030-200305) committed all 14 tasks on main, and by design opened no PR (runs.ts:660). pushSpecStore (ledger.ts:282-307) then rebased the store's branch onto origin with --autostash and pushed it. jobsync's store is in the code repo on main, so the push published every code commit to origin/main of a public repo with no review, and the autostash pop left the operator's uncommitted .gitignore edit in conflict (UU, stash kept). Not decided: refuse a worktree-"no" launch when the project has a remote, or push only when the branch holds spec-store paths alone; and never run rebase --autostash over operator changes outside the store.
