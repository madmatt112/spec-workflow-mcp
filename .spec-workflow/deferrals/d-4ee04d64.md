## Context
Found while writing the simultaneous-start e2e scenario in task 16.1. chokidar watches activeProjects.json by path, but writeRegistry writes a per-process temp file and renames it over the target — so each write replaces the inode the watcher holds. When two registrations land closely spaced, the dashboard can miss one entirely: the registry file on disk is correct and contains both entries, but the dashboard never learns about the second. This is a watcher defect, not a registry defect, and it is distinct from the registry lock task 4 added — the lock makes the file correct, which it now is. It becomes more visible under this spec, because per-worktree identity means N worktrees produce N registrations that genuinely race, where before they converged on one entry. Related to d-3580c072, which is the same watcher going blind after the global directory is recreated.

## Decision Deferred
Not decided: whether the dashboard should watch the containing directory rather than activeProjects.json itself, or whether writeRegistry should write in place rather than rename a temp file over it. Task 16.1 worked around it by polling the registry file rather than relying on the dashboard's view.
