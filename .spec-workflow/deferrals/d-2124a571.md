## Context
Discovered while building the unit-level git fixture (task 1). vitest's worker pool never emits the process 'exit' event, so a process.on('exit') teardown handler — the obvious and conventional choice — silently never fires and every fixture temp directory survives the run. Task 1 worked around it with an exported cleanupAllGitFixtures() called from afterAll, verified empirically both ways. Any temp-directory fixture added by worktree-review-signals (TaskStateStore on-disk store) or worktree-dashboard-concurrency (N-worktree registry and lock fixtures) hits the same trap. A related pre-existing instance already exists in the repo: src/__tests__/index-entrypoint.test.ts:18 leaks a specwf-entrypoint-* directory on every run.

## Decision Deferred
Not decided: whether the test-fixture teardown convention established in task 1 (an exported cleanup function invoked from an explicit afterAll hook) should be codified for the fixtures the two deferred worktree specs will add, or left to each spec to rediscover.

## Revisit Criteria
A tasks.md in either deferred spec proposes a new on-disk test fixture, or someone fixes the index-entrypoint.test.ts leak.
