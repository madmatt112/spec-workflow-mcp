## Context
Found while writing the e2e scenarios in task 16.1. toMCPResponse encodes tool output as TOON, but the output it produces for review-task and adversarial-review cannot be decoded by the same library — the methodology field is what breaks it. Any consumer that round-trips a response through the encoder, including an agent or a test asserting on structured output, gets a decode failure rather than the data. This is outside worktree-execution-context's scope: it is a response-encoding defect that predates the spec and affects these tools regardless of worktrees. It matters to worktree-review-signals, which owns the disclosure channel carrying execution context into the reviewing agent's prompt and will need a response shape that survives round-tripping.

## Decision Deferred
Not decided: whether toMCPResponse should fall back to JSON for payloads TOON cannot round-trip, whether the methodology field should be excluded from the encoded payload, or whether the encoder needs fixing. Task 16.1 worked around it in the e2e scenarios rather than changing the response shape.

## Revisit Criteria
worktree-review-signals drafts requirements for R9 (disclosures reach the reviewing agent), or a decode failure is reported against either tool's output.
