## Context
The design made deploy fire-and-forget (outcome 'started'; the script reports its own failures), waving off script-reported failures but not spawn-level failures. Production ships the script at the checkout root (CONTROLLER_HARNESS_REPO), so likelihood is low. A single child.on('error', ...) that logs to deploy.log would close the gap. Surfaced as an info finding in the task-11 review.

## Decision Deferred
execDeploy spawns sdd-self-update.sh detached and unref'd with no 'error' listener. If the script is missing or non-executable at the resolved checkout root, Node emits an unhandled 'error' event that becomes an uncaught exception and can crash the dashboard server.

## Revisit Criteria
When the deploy executor is next touched, or if the dashboard server is observed crashing after a confirmed deploy.
