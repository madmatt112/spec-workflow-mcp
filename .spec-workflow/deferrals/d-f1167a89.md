## Context
Verifier task-12 review, spec dashboard-ruling-view, round 0. The stale entry is inert: stages.stages.has(answerKey) is read only when openWaitId is set and keys are per-wait, so it never resurrects the view or crosses waits. Only visible effect is a brief stale 'failed: …' when the SAME still-open wait is reopened after a failed answer, cleared on the next press. No task-12 success criterion exercises it; gate and all named checks pass. A proper fix would add a clear(key) method to useStages (src/dashboard_frontend/src/modules/shell/useStages.ts), which task 12's File list omits and its restriction forbids.

## Decision Deferred
Design C9 says "Back to board clears the key's stage too", but HomePage.backToBoard (and the done-path effect) clears only openWaitId/openWaitSnapshot, leaving the wait:<id> entry in stages.stages. The useStages hook exposes no imperative clear and task 12's restriction forbids changing it, so the literal clause was not implemented.
