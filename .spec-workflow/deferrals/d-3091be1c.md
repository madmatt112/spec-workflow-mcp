## Context
Verification attempted 2026-09-21 on run run-20260921-223600 (first live run after PR #54 merged, npm run build, session restart) and FAILED. The SubagentStop hook did write a spawn.end row for sdd-closeout-orchestrator with numeric usage and a model string, but the values are the parent session transcript's, not the orchestrator's: row input 5516 / output 430585 / cacheWrite 5001644 / cacheRead 46447696 / tokens 51885441 / model "claude-fable-5-1+<synthetic>", while the orchestrator transcript (agent-a91016c9ea9a0c2d1.jsonl, 77 assistant entries, all claude-opus-4-8) sums to 5843386. Cause: harness/hooks/sdd-activity.sh readUsage(d.transcript_path) reads the session transcript the payload names; the subagent's own transcript path (agent_transcript_path in the SubagentStop payload, if present) must be used, with transcript_path as fallback. Two identical rows were also written 15 minutes apart, so the stop fires twice per orchestrator. Original context: The SubagentStop hook is the single writer of per-spawn usage. End-to-end scenario 2's live half needs a real session's SubagentStop firing for a supervisor-spawned orchestrator, which requires the checkout rebuilt and the session restarted. Design D13's planned deferral.

## Decision Deferred
The live proof that a supervisor-spawned orchestrator's SubagentStop writes a spawn.end row carrying numeric input/output/cacheWrite/cacheRead/tokens and model was not exercised end-to-end in a live session.

## Revisit Criteria
After npm run build and a session restart, run one SDD phase through the supervisor and confirm the orchestrator's spawn.end row in that spec's .spec-workflow/specs/<spec>/harness-events.jsonl carries numeric input, output, cacheWrite, cacheRead, tokens and a model string (not tokens=unknown), with the tokens total equal to the sum of message.usage over that orchestrator transcript's assistant entries.
