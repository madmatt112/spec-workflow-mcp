## Context
On 2026-11-04, POST /api/controller/runs/run-20261104-031427/cancel set the status to abandoned and stopped the drafter. The driver then started a second drafter at 03:17:16.741. That process (PID 13938) ran for about 50 seconds with the run marked abandoned. After overwatch stopped it by PID, the driver read the step as schema-invalid, opened error wait w-450be37d and wrote status waiting over abandoned. Answering abandon on that wait ended the run. A later ledger write recreated the deleted spec folder. cancelRun in src/controller/runs.ts stops the in-flight process and writes the status, but the root cause in the driver loop was not diagnosed.

Second reproduction, 2026-11-04 20:55Z, run-20261104-205502 (dashboard-deploy, requirements). The same sequence occurred: cancel returned ok and the status was abandoned, a second drafter (PID 624044) started, stopping it by PID opened error wait w-eb67753f and wrote status waiting, and answering abandon ended the run. The discard route then removed the worktree and the branch. The spec folder was removed by hand and no later write recreated it.

## Decision Deferred
How the driver must stop after a cancel. Decide where the step loop checks isCancelled so that no new step starts and no later write replaces the abandoned status.

## Revisit Criteria
Next swm harness batch, or the next time an operator cancels a running run
