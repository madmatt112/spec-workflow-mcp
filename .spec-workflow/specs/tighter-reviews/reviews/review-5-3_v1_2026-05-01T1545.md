## Summary

Implementation faithfully fulfills the task's requirements (chunked async realpath, ENOENT bucketing, case-fold, normalized set ops with original-path output, dedup-by-normalized, in-scope tagging, denylist filtering, in-scope-first 100-cap on the post-denylist set). Several non-blocking concerns: non-ENOENT realpath errors are warned BUT also bucketed as excluded (debatable interpretation of "do not silently swallow"), suppressedDenylistedFiles can double-count when the same denylisted path appears across compiled/excluded/diagnostic-files, and partitionPaths is invoked three times per call (minor inefficiency).

## Findings

### WARNING: Non-ENOENT realpath failures are bucketed as `excluded` in addition to warning
- **File:** /home/mcf/reference/spec-workflow-mcp/src/core/typecheck.ts:86
- **Issue:** When `fs.realpath` rejects with a non-ENOENT code, `realpathChunked` calls `warnRealpathOnce` and then pushes `{ original, normalized: undefined }`. In `postProcess`, undefined-normalized entries fall through to the `excluded` array (line 213-218). The task restriction says: 'ENOENT realpath errors bucket as `excluded`, all other realpath errors propagate via warn-once (do NOT silently swallow)'. The implementation warns (so not strictly silent), but it also silently treats EACCES/EIO/etc. as if they were ENOENT for bucketing purposes. A stricter reading of 'propagate' would re-throw or surface a separate channel; a looser reading is satisfied by the warn-once. Worth confirming the intent — currently a permission error on a real file would be reported as `excluded` (i.e. not type-checked), which is a misleading signal.
- **Task Requirement:** R2.4 / task 5.3 restriction: 'all other realpath errors propagate via warn-once (do NOT silently swallow)'

### WARNING: `suppressedDenylistedFiles` can double-count across the three `partitionPaths` calls
- **File:** /home/mcf/reference/spec-workflow-mcp/src/core/typecheck.ts:243
- **Issue:** `postProcess` calls `partitionPaths` three times (compiled, excluded, diagnostic file paths) and sums `skipped.length` from all three (line 243-246). A single denylisted path that is in `excluded` and also is the file of N diagnostics will contribute 1 + N to the count rather than 1 unique file. The task spec describes the field as 'Surface dropped count as `suppressedDenylistedFiles`' — ambiguous as count-of-occurrences vs count-of-unique-files, but R2.13/design language says 'dropped count' suggesting unique files. Recommend deduplicating by normalized form before counting, or document that the value is occurrence-count.
- **Task Requirement:** task 5.3: 'Surface dropped count as `suppressedDenylistedFiles`'

### INFO: Diagnostic denylist filter uses raw `d.file` instead of normalized form
- **File:** /home/mcf/reference/spec-workflow-mcp/src/core/typecheck.ts:237
- **Issue:** Line 237 calls `partitionPaths(diagFiles)` on the raw diagnostic file strings, and line 238 builds `keptDiagFiles` from those raw strings. This is consistent with how `compiled`/`excluded` are filtered (raw originals), and `partitionPaths` itself is segment/basename based so it does not require normalization to be correct. However, if tsc ever emits a diagnostic file path that differs in case from how it was passed in (e.g. on case-insensitive volumes), the kept-set membership check is exact-string. Low risk — tsc on a given platform is consistent within a run — but worth noting that the diagnostic filter does not benefit from the normalization that `compiled`/`excluded` set ops use.

### INFO [hygiene]: Module-level `realpathWarnedKeys` Set grows unboundedly across calls
- **File:** /home/mcf/reference/spec-workflow-mcp/src/core/typecheck.ts:59
- **Issue:** The module-private `realpathWarnedKeys` set (line 59) is intentionally global to give 'warn-once' semantics across the lifetime of the process, but it has no eviction. Long-running processes that exercise many distinct error/path combinations could accumulate memory. Acceptable for v1 (warns are by definition rare), but worth a comment noting the unbounded growth.

### INFO [hygiene]: Three sequential realpath passes could be parallelized
- **File:** /home/mcf/reference/spec-workflow-mcp/src/core/typecheck.ts:200
- **Issue:** `postProcess` awaits `realpathChunked(allFiles)`, then `realpathChunked(listFilesOutput)`, then `realpathChunked(diagFiles)` strictly sequentially (lines 200, 201, 228). These three calls are independent — wrapping them in `Promise.all` would halve wall-clock latency on large projects. Not a correctness issue and not required by the task; logging here for future tuning.

### INFO [hygiene]: `console.warn` at line 65 is intentional, not a leftover
- **File:** /home/mcf/reference/spec-workflow-mcp/src/core/typecheck.ts:65
- **Issue:** The pre-computed hygiene signal flags `console.warn` at line 65, but this is the warn-once mechanism required by the task restriction ('warn-once, do NOT silently swallow'). Confirmed intentional — no action required. Logging explicitly so the signal is closed out.
