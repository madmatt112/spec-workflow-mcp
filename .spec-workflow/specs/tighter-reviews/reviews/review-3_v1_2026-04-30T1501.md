### INFO: Parsed-shape warn-once keys not scoped per-(absPath, cause) like load warnings
- **File:** src/core/adversarial-settings.ts:138
- **Issue:** Load warnings are keyed by 'load:<absPath>:<cause>' and cleared on (mtime, size) advance. Parsed-shape warnings (runner-block-non-object, runner-model-non-string, legacy-model-non-string, features-non-object, features-typecheck-non-boolean) use process-lifetime dedup keys without absPath, so two different project paths with identical shape errors share a single warn slot, and a fix-then-rebreak with the same shape doesn't re-warn. R3.7 strictly mandates the cleared-on-advance behavior only for load warnings; R3.5/R3.12 just say 'warn-once'. Spec is satisfied; symmetry could be tightened.
- **Task Requirement:** R3.5/R3.7/R3.12 (asymmetry note)

### INFO [hygiene]: Cached settings object returned by reference (mutation hazard)
- **File:** src/core/adversarial-settings.ts:78
- **Issue:** loadSettings returns cached.settings directly. A caller mutating the result would poison the cache for the (mtime, size) window. Current consumers don't mutate. Defensive Object.freeze before caching, or structuredClone on read, would harden.
