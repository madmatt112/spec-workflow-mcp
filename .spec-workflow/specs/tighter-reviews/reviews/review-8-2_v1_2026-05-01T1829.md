### INFO: warnOnce key includes utility+message but interleaves with validateAllFiles keys in same Set
- **File:** /home/mcf/reference/spec-workflow-mcp/src/tools/review-task.ts:13
- **Issue:** The restriction requires `(utility, error.message)` as the warn-once key for unwrap rejections — the implementation encodes this as `unwrap:typecheck:${message}` and `unwrap:hygiene:${message}` (review-task.ts:104, 121), which is structurally correct. However, the same `validateWarnedKeys` Set (line 13) is shared by validateAllFiles, safeRealpath, and both unwrap helpers. A pathological collision would require validateAllFiles to emit a warning whose message-derived key equals `unwrap:typecheck:<some message>` — extremely unlikely given the prefix conventions, but the prefixes are not documented as a namespacing contract. If a future utility is added with a key that omits a prefix, dedup could silently swallow a legitimate warn. Consider documenting the `<scope>:<detail>` prefix convention as a comment near `validateWarnedKeys`, or splitting the unwrap warn sink into its own Set per the design's '(utility, error.message)' framing.
- **Task Requirement:** Restriction: unwrap* warn-once key MUST be (utility, error.message)
