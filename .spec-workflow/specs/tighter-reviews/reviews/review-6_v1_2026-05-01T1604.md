## Findings

### WARNING: Absolute-path-leak test passes vacuously: compiled is empty by construction
- **File:** /home/mcf/reference/spec-workflow-mcp/src/core/__tests__/typecheck.test.ts:379
- **Issue:** In the test 'absolute path inside diagnostic message head does NOT pollute compiled set' (lines 379-394), `runProjectTypecheck` is called with `allFiles=[]`. Since `coverage.compiled` is `listFiles ∩ allFiles`, it is necessarily an empty array — so `expect(result[0].coverage.compiled).not.toContain('/abs/leaked/path.ts')` passes regardless of whether the parser leaks the embedded path into listFiles. The test's own inline comment acknowledges this. The remaining assertion (the message contains the path) only proves the diagnostic head was captured, not that the path was excluded from listFiles. To make this load-bearing, pass `allFiles=['/abs/leaked/path.ts']` (writing the file or accepting the ENOENT-as-excluded path) and assert that '/abs/leaked/path.ts' ends up in `coverage.excluded`, never `coverage.compiled` — which would fail if the parser ever lifted the message-embedded absolute path into listFiles.
- **Task Requirement:** 5.2 — absolute-path-in-error-message excluded from compiled set
