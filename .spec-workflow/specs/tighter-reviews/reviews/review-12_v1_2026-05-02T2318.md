## Findings

### INFO [hygiene]: Rename detection mismatch between -M diff and bare numstat may bypass per-file cap
- **File:** src/core/task-diff.ts:65
- **Issue:** computeTaskDiff invokes the unified diff with -M (rename detection) but the numstat invocation has no -M flag. With -M, the diff body uses `diff --git a/<old> b/<new>` and splitDiffSections keys the section by the new path. Without -M on numstat, a pure rename appears either as no entry (rename with no content change is collapsed by git) or as separate add/delete entries with different paths. Result: numstat.perFile.get(sec.filePath) returns undefined for renamed-with-edits files, and the per-file 500-line cap (line 65) is silently skipped for those files because the guard is `if (stat && ...)`. Edge case — pure renames are tiny anyway, and rename-with-large-edits is rare — but if a reviewer ever sees an enormous renamed-file hunk slip past the cap, this is the cause. Cheapest fix: pass -M to numstat too so paths align.
- **Task Requirement:** R1.9

### INFO [hygiene]: DIFF_HEADER_RE does not match git's quoted paths (spaces / non-ASCII filenames)
- **File:** src/core/task-diff.ts:16
- **Issue:** DIFF_HEADER_RE is `/^diff --git a\/(.+) b\/(.+)$/`. When a path contains spaces or non-ASCII characters, git emits the header as `diff --git "a/path with space" "b/path with space"` (controlled by core.quotepath). The current regex does not match the quoted form, so splitDiffSections returns no section for that file — its diff body is dropped from the output (everything before the next matching header is silently discarded). Numstat counts still reflect it, so stats and diff body desync for those files. Likely rare in this codebase, but worth noting as a known soft-spot. A fix would optionally accept `"a/(.+)" "b/(.+)"` and unescape git's C-style quoting.
- **Task Requirement:** R1.1

### INFO [hygiene]: parseNumstat counts every numstat row toward filesChanged, including those filtered out as binary in the diff body
- **File:** src/core/task-diff.ts:161
- **Issue:** parseNumstat increments filesChanged for every tab-separated row regardless of whether the file is binary. computeTaskDiff strips Binary file sections from the displayed diff but the returned stats.filesChanged still counts those binary files (numstat shows them as `-\t-\t<path>`, parsed as 0/0). This matches what `git diff --numstat` itself reports so it is arguably the canonical answer, and R1.8 explicitly says numstat is the canonical source — but the reviewer-facing diff shows N-binary fewer files than stats.filesChanged claims. Worth flagging as expected-but-potentially-confusing rather than a defect.
- **Task Requirement:** R1.8
