### INFO: normalizeForPin collapses paragraph breaks via /\s+/g
- **File:** /home/mcf/reference/spec-workflow-mcp/src/tools/__tests__/review-task.test.ts:533
- **Issue:** normalizeForPin (src/tools/__tests__/review-task.test.ts:533) applies `.replace(/\s+/g, ' ')` to BOTH sides of the composite-pin comparison. For Track A this is permitted by the explicit restriction (Track A doesn't need block-boundary detection). However, the success-with-diagnostics-and-partial-coverage fixture has a deliberate paragraph break between R4.4 and R4.5 (line 28 of the fixture). Collapsing all whitespace means a regression that fused R4.4 and R4.5 into one paragraph (or removed the blank line between them) would NOT be caught by these pin tests. The composition section of that fixture explicitly calls out 'R4.4 then a paragraph break then R4.5' as a pinned property — but the normalizer erases exactly that property. Consider documenting this gap with a comment, or for the partial+diagnostics scenario specifically, also assert the un-normalized methodology contains '\n\n**Partial typecheck coverage' so the paragraph-break property is pinned somewhere. Track B (task 17) drift test will likely catch this, but Track-A interim leaves it unpinned.
- **Task Requirement:** composite-pin equality after full normalization
