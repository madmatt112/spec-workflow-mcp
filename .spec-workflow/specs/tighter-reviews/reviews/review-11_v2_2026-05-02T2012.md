## Findings

### WARNING [hygiene]: Concurrency test relies on real wall-clock timers (potential flakiness)
- **File:** src/tools/__tests__/review-task.test.ts:720
- **Issue:** The overlap test uses real setTimeout(60ms) and Date.now() comparisons. On slow CI runners or under heavy contention, scheduling jitter could let one promise run to completion before the other's setTimeout resolves the microtask queue, leaving overlap unobserved despite the implementation being concurrent. Replace with explicit barrier promises (e.g. each utility awaits a shared deferred that is resolved only after both have started) so overlap is guaranteed by construction.

### WARNING: Composite-pin paragraph-break assertion only covers one of seven fixtures
- **File:** src/tools/__tests__/review-task.test.ts:523
- **Issue:** normalizeForPin collapses all whitespace via /\s+/ → ' ', erasing every \n\n boundary in both fixture and actual methodology. The un-normalized contains-assertion at lines 862-866 only fires for the with-diagnostics-and-partial-coverage scenario. The restriction explicitly says 'split on \n\n first' — which would give equivalent block-ordering guarantees for the item9 → item10 transition in every scenario. Consider splitting both sides on /\n\n+/ before per-block normalization so block ordering is pinned across all seven fixtures.
- **Task Requirement:** Restriction: split on \n\n first; do not collapse paragraph breaks before block-boundary detection
