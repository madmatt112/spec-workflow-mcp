## Decisions taken in this document

- D1 — Report sentences in ported briefs: options were replacing each brief's report sentence with the role's key block, or porting the 150-word sentences verbatim beside the new agent bullets; chosen because a brief and its agent file that disagree on the report shape leave the worker to pick one, and Requirement 5.1 caps every report.
- D2 — Append mode lands with the reviewer kind in task 8: options were the move task 7, or task 8; chosen because no kind uses append mode before the reviewer kind exists, so task 7 stays a pure move with no edited test.
- D3 — The brief template work is four tasks (move, document kinds, implementation kinds, script kind): options were one task, two, or four; chosen because each block stays under the word cap and each review covers one briefs file.
- D4 — The implementation briefs file's PR body rules move to the completion reference, and the agent rules' PR body section is read as one section: options were the completion reference, a new brief kind, or the core skill; chosen because only the completion gate opens the PR, and Requirement 4.1 forbids a whole read of the agent rules.
- D5 — The sources block formatter and its shapes sit in the pure source module: options were the source module, or the tool file; chosen because Requirement 1.10 wants the breakdown logic pure and tested in the watch directory, and the tool file then only does input and output.
- D6 — Scenario 1 is recorded in the evidence file by the baseline task, and a diff over 1% stops that task as a design defect: options were the baseline task, or the final gate; chosen because the transcripts may age out before the final gate, and a failed sum means the attribution rule is wrong, which is a design question.
- D7 — The baseline task calls the action from the worktree build through a scratch script: options were a scratch script over the built handler, or waiting for a merged build; chosen because the session's server is the main checkout build, which lacks the option until merge, and waiting risks the transcripts.
- D8 — The fixture kit writes no event script and no spec folder: options were a kit with its own event script, or none; chosen because the live run goes through the supervisor, which writes the run's own event script, and an empty spec folder would be routed before the run.
- D9 — Doc updates sit in the tasks that change each surface (tool reference in tasks 4, 6 and 10; harness guide in tasks 13 and 14): options were per-surface tasks, or one docs task at the end; chosen because the design puts the docs in the same tasks and each implementer knows its own surface.
- D10 — The skill-split test is written in task 12 with a frozen heading list of both skills and extended in task 13: options were one test per skill, or one shared test grown in two steps; chosen because one frozen list from the base commit covers both skills, and the implementation skill's headings still pass in task 12 before its split.
