# Implementation Log: Task 11

**Summary:** Added the design C8 watchView to the WebSocket context and copied the harness wire shapes into the frontend tree. watchView(view) takes { kind: 'harness', projectId } or { kind: 'overview' }, keeps a reference count per view key, sends harness-subscribe/overview-subscribe when the first caller registers and the socket is open, sends the matching unsubscribe when the last caller releases, and re-sends every held view's subscribe on onopen after a reconnect. onmessage now routes overview-rows and overview-todos to their handlers by type with no project check, exactly like projects-update; harness-* messages carry projectId and continue through the existing project-scoped branch, so initial, projects-update and existing project handling are unchanged. #### Integration
- **Description:** A page calls useWs().watchView({ kind: 'overview' }) or { kind: 'harness', projectId } in an effect; the provider sends the subscribe over the WS, the server hub (C7) starts/stops the matching watch, and overview-rows/overview-todos or harness-* messages flow back to handlers registered via subscribe().

- **Backend Endpoint:** WS /ws harness-subscribe/overview-subscribe handlers (src/dashboard/multi-server.ts)
