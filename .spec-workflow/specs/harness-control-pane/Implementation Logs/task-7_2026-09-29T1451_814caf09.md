### Integrations

#### Integration
- **Description:** ProjectHarnessWatch subscribes to HarnessLauncher's 'launch-update' event for its projectId. Every update schedules a rebuild (refreshing harness-model.launch = launcher.get); only an update whose logPath differs from the current one re-derives the path from launcher.get(projectId), resets the byte offset to 0, clears kept lines, re-arms the log file watch and sends a reset:true harness-log batch with the new launchedAt. When the model's runId is set with runStartedAt >= the record's launchedAt and differs from the record, it calls launcher.noteRunId(projectId, runId) (Req 3.6).
- **Frontend Component:** harness subscribers via C7 hub (sendToHarness); consumed later by HarnessPage (C8)
- **Backend Endpoint:** HarnessLauncher.launch-update event; HarnessLauncher.get / HarnessLauncher.noteRunId (src/dashboard/harness/launcher.ts)
- **Data Flow:** launcher writeRecord -> emit('launch-update', {...record}) -> ProjectHarnessWatch.onLaunchUpdate -> schedule rebuild and (on logPath change) re-arm log watch + send reset batch
