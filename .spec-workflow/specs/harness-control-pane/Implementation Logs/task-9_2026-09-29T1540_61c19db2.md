### Integrations

#### Integration
- **Description:** HarnessHub reconcile is called by MultiProjectDashboardServer after every /ws subscription change (harness-subscribe/unsubscribe, overview-subscribe/unsubscribe, and the existing subscribe) and both connection removal paths (the ws cleanup closure and scheduleConnectionCleanup). A harness/overview subscribe then sends hub.snapshotFor(projectId)/hub.overviewSnapshot() to the subscribing socket alone. Hub messages flow back through sendHarness/sendOverview callbacks wired to server.sendToHarness(projectId,msg)/sendToOverview(msg), which filter open clients by connection.views (and projectId for harness) instead of broadcastToProject.
- **Frontend Component:** ws client (HarnessPage / OverviewPage, task C8)
- **Backend Endpoint:** MultiProjectDashboardServer /ws message handler; HarnessHub.reconcile / snapshotFor / overviewSnapshot
- **Data Flow:** ws harness-subscribe -> connection.views.add('harness') -> hub.reconcile(clients) starts ProjectHarnessWatch -> snapshotFor sent to this socket; ledger/HUD fs change -> watch send callback -> server.sendToHarness/sendToOverview -> filtered ws send
