# Implementation Log: Task 1

**Summary:** Design C1: split the merge read so one pass returns everything the PR panel needs. Added `url` to PR_VIEW_FIELDS (still one `gh pr view` per pass). Moved evaluate's body into a new exported `evaluatePullRequest(pr, now?)` returning `{ evaluation, ci, mergeable?, url? }`; `evaluate` is now a thin wrapper returning `.evaluation`, so its object is byte-identical to base. `ci` is `unreadable` on each of the five early returns; else derived from new `ciFailed`/`ciPending` flags: `red` if a run/status failed, `pending` if a run/status pending or the fresh-head rule fired, else `green`. `mergeable=UNKNOWN` sets the evaluation's `pending` but not `ciPending`. Raw `mergeable` and `url` are read right after the JSON parses, so present on every post-parse return; `url` is `pr.url` ?? the view's `url` string (no https filter; task 2 filters).
