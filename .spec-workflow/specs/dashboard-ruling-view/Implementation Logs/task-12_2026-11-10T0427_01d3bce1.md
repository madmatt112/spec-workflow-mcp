# Implementation Log: Task 12

**Summary:** HomePage keeps a snapshot of the open controller wait and shows the ruling view until the answer stage (keyed wait:&lt;id&gt;) resolves done, instead of hard-coding stage={null}. Added openWaitSnapshot state updated from the live needsYou wait while it's present; when it drops out, the view keeps rendering from the snapshot as long as stages.stages still holds the wait:&lt;id&gt; key. stages.retained(key, { run }) (run looked up from controllerRuns by wait.run) now drives RulingView's stage prop, so answer-stage renders pressed/running/failed/done and the submit button disables while busy. An effect clears openWaitId (and the snapshot) once the stage reaches done, returning to the board; Back to board does the same clear on click. Also fixed an author-test assertion in e2e/worktree-ruling.spec.ts (task 12 case 8) that checked the quiet-only run-status-&lt;id&gt; testid for a run parked paused in the Running band (per board.ts's MOVING_STATUSES/AC 6.14, a paused run stays in Running, not the quiet Stopped band, so that testid never renders there); replaced it with a toContainText('paused') check on the run tile itself.
