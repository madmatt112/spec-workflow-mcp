### Functions

#### normalizeIdentityPath
- **Purpose:** Absolute, realpath-normalized form of a path, for use as an identity key. Behaviour: realpath(resolve(p)) — relative input is resolved against process.cwd() first, so the result is always absolute. STATED FALLBACK: when realpath fails (directory removed, as after `git worktree remove`, or unreadable) it returns the un-normalized absolute path resolve(p). The fallback is deterministic — two computations of the same input agree — which is what makes it safe for identity hashing in task 15. Note it does NOT partially normalize: whole-path realpath failed, so no symlink in the surviving prefix is resolved. It does not log; requirement 1.12's logging is task 15's, not this task's requirement set. Exported.
- **Location:** src/core/git-utils.ts
- **Signature:** normalizeIdentityPath(p: string): string
- **Exported:** No

#### gitCommonDirAbsolute
- **Purpose:** Absolute, realpath-normalized git common directory for cwd; null when cwd is not in a repository, the path does not exist, or git is unavailable. Exactly realpath(resolve(cwd, raw)) — NO component stripped. Verified against real git output for: '.git' at a repo root, '../../../.git' from a subdirectory at depth, absolute <main>/.git from sibling and nested worktrees, <super>/.git/modules/<name> from a submodule, '.' in a bare repo and from inside a .git directory, and the external dir under --separate-git-dir (which contains no '.git' segment at all). DO NOT reuse resolveGitRoot's normalization at git-utils.ts (the lastIndexOf('.git') block) — empirically verified: substituting it turns 8 gitCommonDirAbsolute cases plus the superproject-vs-submodule case red. Exported.
- **Location:** src/core/git-utils.ts
- **Signature:** gitCommonDirAbsolute(cwd: string): string | null
- **Exported:** No

#### gitTopLevel
- **Purpose:** Absolute, realpath-normalized `git rev-parse --show-toplevel`, or null on failure. Verified null in a bare repository and from inside a .git directory — both of which still return a usable common directory, which is exactly why requirement 1.7 needs it as a separate gate. This function does NOT gate sameRepository; the caller (task 4's resolveWorkspaceRoots) must require a non-null result on both sides before inference fires. Exported.
- **Location:** src/core/git-utils.ts
- **Signature:** gitTopLevel(cwd: string): string | null
- **Exported:** No

#### sameRepository
- **Purpose:** True only when both paths are in a git repository and it is the same one. Returns false when EITHER side's common directory is null, so two non-git directories never compare equal (verified, including one non-git directory against itself). Compares common directories DIRECTLY, never a derived parent, so a superproject and its submodule compare false (requirement 1.5). Does not gate on toplevel — see gitTopLevel. Exported.
- **Location:** src/core/git-utils.ts
- **Signature:** sameRepository(a: string, b: string): boolean
- **Exported:** No

#### gitExecOptions
- **Purpose:** THE scrub point for requirement 1.9 / 2.12. Returns { ...GIT_EXEC_OPTIONS, cwd, env } where env is a copy of the live process.env with GIT_DIR, GIT_COMMON_DIR, GIT_WORK_TREE and GIT_INDEX_FILE deleted. Rebuilt per call, not snapshotted at module load, so a variable exported after import is still scrubbed (unit-tested). Every execSync in the module MUST take its options from this function — a source-scanning test enforces it. Not exported.
- **Location:** src/core/git-utils.ts
- **Signature:** gitExecOptions(cwd: string): ExecSyncOptionsWithStringEncoding (module-private)
- **Exported:** No

#### gitCapture
- **Purpose:** Runs a git command in cwd with gitExecOptions and returns trimmed stdout, or null when it fails or produces no output. Never throws — the fail-closed wrapper the new helpers use. The three pre-existing functions keep their own try/catch bodies unchanged so their empty-output behaviour is untouched.
- **Location:** src/core/git-utils.ts
- **Signature:** gitCapture(command: string, cwd: string): string | null (module-private)
- **Exported:** No
