#### withRegistryLock
- **Purpose:** Runs fn under an exclusive file lock. Returns { acquired: true, value } or { acquired: false, reason: 'timeout' | 'error', error? } — it NEVER throws on acquisition failure, because registerProject is awaited before the MCP transport connects and throwing kills the handshake (R6 AC 4). fn's own errors propagate; the lock is released in a finally. Order matters: it mkdirs dirname(lockPath) FIRST, because ProjectRegistry.ensureRegistryDir runs inside the critical section, so on a first run fs.open(lockPath,'wx') would fail with ENOENT rather than EEXIST (R6 AC 2). Options default to timeoutMs 5000 / staleMs 30000 / retryIntervalMs 25 (exported as DEFAULT_LOCK_TIMEOUT_MS, DEFAULT_LOCK_STALE_MS, DEFAULT_LOCK_RETRY_INTERVAL_MS). Scoped to the registry writers only (R6 AC 6) — the other four shared-root files belong to worktree-dashboard-concurrency. Exported. REUSE THIS for any further registry writer rather than hand-rolling a second lock.

#### uniqueTempPath
- **Purpose:** Returns `${basePath}.${process.pid}.${counter}.tmp` from a module-level counter shared with the rename-aside names, so every temp/aside file this process creates is unique (R6 AC 3). ProjectRegistry.writeRegistry now calls uniqueTempPath(this.registryPath) instead of the shared `${this.registryPath}.tmp`; a shared temp name lets two concurrent writers interleave bytes into one file, which rename atomicity cannot fix because both renames move the same corrupted file. Exported.

#### acquireLock
- **Purpose:** The retry loop. fs.open(lockPath,'wx') is the acquisition; ONLY error.code === 'EEXIST' is treated as contention. Any other errno (ENOENT, EACCES, ENOTDIR…) is logged and returned as reason 'error' immediately — a loop that treats every failure as contention burns the whole budget and leaves every process unregistered. A successful stale break retries immediately instead of sleeping. Not exported.

#### breakStaleLock
- **Purpose:** R6 AC 5. Staleness comes from fs.stat mtimeMs — never from a self-reported timestamp inside the lock file, and never from ProjectRegistry.isProcessAlive, which returns true unconditionally when both Docker path-translation variables are set and would make a crashed container's lock permanently unbreakable. Breaking is a rename to `${lockPath}.${pid}.${counter}.stale`; only the process whose rename succeeded returns true and proceeds. Empirically verified against the naive alternative: replacing the rename with unlink-ignoring-failure turns the 4-process stale test red (2 of 4 children broke and acquired). Logs '[registry-lock] Broke a stale lock at …' — the test counts those log lines to prove exactly one breaker won. Not exported.
- **Location:** src/core/registry-lock.ts:66
- **Signature:** breakStaleLock(lockPath: string, staleMs: number): Promise<boolean>
- **Exported:** No

#### releaseLock
- **Purpose:** Closes the handle, then unlinks lockPath ONLY if the file still carries our token. If our lock was broken aside and another process now owns the file, that file is left alone. Lock file contents are {pid, hostname, token} per the design's data model; the token is `${pid}-${Date.now()}-${counter}`. Not exported.
