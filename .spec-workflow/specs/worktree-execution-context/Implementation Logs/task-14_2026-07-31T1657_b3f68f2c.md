#### selectRoots
- **Purpose:** THE override entry point for the four tools of requirement 3.8. Returns { workflowRoot, workspacePath }. No override (absent, empty, or non-string args.projectPath) -> { context.projectPath, context.workspacePath } verbatim and git is never invoked, so requirement 3.11 parity is structural, not incidental. A non-empty string override -> workspacePath IS the override and workflowRoot is derived from it (requirement 3.6); one warnOnce names the override, the discarded context.workspacePath and the derived root (requirement 3.5). Non-string overrides deliberately fall back to the context rather than being passed to execSync as a cwd. Exported. Used by review-task.ts:~240, log-implementation.ts:~311, adversarial-review.ts:~55, adversarial-response.ts:~53 — DO NOT add the remaining override sites (deferrals, get-task-review, spec-index, spec-status, approvals): they read only .spec-workflow and requirement 3.8 excludes them by criterion.

#### deriveUncached
- **Purpose:** THE classification. resolveGitRoot returns its input unchanged in FIVE situations, four of which are silent degradations that must warn (requirement 3.7) and one of which is correct. When the returned root differs from the override the derivation genuinely ran — no probe, no warning. When it equals the override, ONE extra gitCommonDirAbsolute call tells the cases apart: null -> git unavailable or not a repository (warn); equal to realpath(<override>/.git) -> a plain MAIN CHECKOUT, the correct answer (NO warning — warning here would fire on the most ordinary override there is); equal to realpath(override) -> bare repository reporting '.' (warn); anything else -> no '.git' segment, the --separate-git-dir layout (warn). Do not replace this with a bare `result === override -> warn` test; that is what produces the false positive on a main checkout.
- **Location:** src/tools/root-selection.ts
- **Signature:** deriveUncached(override: string): { workflowRoot: string; warning: string | null } (module-private)
- **Exported:** No

#### deriveWorkflowRoot
- **Purpose:** Memoization boundary (requirement 3.9). The SPEC_WORKFLOW_SHARED_ROOT arm is handled FIRST and is deliberately NOT cached — it runs no git, and caching it would pin a stale reading across a change to the variable — and it warns that the environment outranks the derivation and nothing was derived from the override. Everything else goes through the bounded cache; the cached entry carries its warning message so repeated calls still warn (warnOnce dedupes) without re-running git.
- **Location:** src/tools/root-selection.ts
- **Signature:** deriveWorkflowRoot(override: string): string (module-private)
- **Exported:** No

#### _resetRootSelection / _rootSelectionCacheSize
- **Purpose:** Test-only hooks: clear the derivation cache plus the warn-once ledger, and read the cache size. The size getter is what lets the bound be asserted without spawning git 40 times against real repositories.
- **Location:** src/tools/root-selection.ts
- **Signature:** _resetRootSelection(): void; _rootSelectionCacheSize(): number
- **Exported:** No

#### remember
- **Purpose:** THE bound. Both the derivation cache and the warn-once ledger are keyed by an agent-supplied string, so both are capped at ROOT_SELECTION_CACHE_LIMIT = 32 (exported) with FIFO eviction — a Map iterates in insertion order, so the first key is the oldest. Cost of an eviction is at most one repeated git derivation, never a wrong answer. An unbounded Map here leaks one entry per call for a client that varies projectPath.
- **Location:** src/tools/root-selection.ts
- **Signature:** remember<V>(store: Map<string, V>, key: string, value: V): void (module-private)
- **Exported:** No
