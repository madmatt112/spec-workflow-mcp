# Tasks Document

Nineteen entries: eighteen numbered tasks plus one sub-task (16.1). The parser's count is authoritative — `spec-status` reports it.

**Dependencies are stated inside each `_Prompt:` field, not in a separate line.** The task parser recognises `_Prompt:`, `_Requirements:` and `_Leverage:` only; a `_Depends:` field lands in free text and never reaches the implementing agent's context. Ordering that an agent cannot see is not ordering.

**Where a task touches N sites, it carries the command that enumerates them, not a hand-written list.** Across four review rounds every hand-counted site list in this spec came up exactly one short — git invocation sites 2→3, typecheck roots 3→5, adversarial routes 2→4, read-every-file instructions 2→4. The counts below are starting points; the commands are the contract.

**Two orderings are load-bearing.** The parity characterization test (2) must pass on the unmodified tree, because written later it can only record what the code then does. The registry lock (4) precedes the change that creates the race it prevents (5).
