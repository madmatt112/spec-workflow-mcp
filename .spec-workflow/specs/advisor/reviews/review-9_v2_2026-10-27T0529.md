## Summary

Fix round 1 implements design D12 (>200-chunk "indexing n of m" + in-process background embed) and all named Success items pass. But the new background embed path has no try/catch: its rejection is detached in a module singleton consumed only by the test-only waitForIndexing, so a mid-index embedder error becomes an unhandled rejection that crashes the host server, violating design Error Handling #7. A no-embedder search still wipes the cached index (recurring INFO).

## Findings

### WARNING: Background embed failure is an unhandled rejection; violates design Error Handling #7
- **File:** src/advisor/search/index.ts:237
- **Issue:** The deferred background embed path (embedDeferred, index.ts:158-165) calls embedder.embed() with no try/catch. The job promise is stored only in the module singleton backgroundJob.promise; in production nothing consumes it (only the test-only waitForIndexing hook awaits it). So if the embedder errors mid-index during the first >200-chunk refresh — embed() throws on !res.ok and fetch rejects on network error (Ollama 5xx / dropped connection) — the rejection is unhandled and, under Node's default --unhandled-rejections=throw, terminates the dashboard/controller process that hosts search(). Design Error Handling #7 requires the opposite: 'Embedder unreachable mid-refresh: refresh stops, the index keeps what it wrote, result says meaning: off.' The background job also persists deferred vectors only after the full loop (index.ts:174-179), so a mid-job failure discards all partial progress instead of keeping what it wrote. The synchronous <=200 path (index.ts:208) has the same missing catch (search() rejects to the caller instead of meaning:off), present since the original build. Fix: wrap the background (and synchronous) embed in try/catch, stop the refresh, keep what was written, clear backgroundJob, and surface meaning 'off' rather than reject/crash.
- **Task Requirement:** design C6 / Error Handling #7; NFR Performance / D12

### INFO: A no-embedder search wipes the cached project index (recurring, review-9_v1)
- **File:** src/advisor/search/index.ts:124
- **Issue:** buildPlan sets model = embedder?.model ?? '' (index.ts:124); when search.json is absent or the embedder is briefly down, readIndex returns empty files (stored model != '') and the !embedder branch's writePlan (index.ts:197) overwrites each project index with model='' and undefined vectors, discarding all cached vectors. When the embedder returns, the whole corpus re-embeds (now via the D12 background job). Not a named Success item and the design does not mandate cross-outage preservation, but it defeats the cache NFR Performance relies on. Flagged INFO in review-9_v1; the fix round did not address it.
- **Task Requirement:** design C6 (index files / model change)
