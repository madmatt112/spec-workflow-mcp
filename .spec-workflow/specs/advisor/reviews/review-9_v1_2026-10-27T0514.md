### CRITICAL: NFR Performance progress clause / design D12 silently dropped
- **File:** src/advisor/search/search.ts:79
- **Issue:** The task _Prompt requires: 'over 200 chunks to embed it returns text hits with meaning "indexing n of m" and keeps embedding in process (design D12)'. Cited requirement NFR Performance: 'the first full index may run longer and SHALL report progress'. Design C6: 'Over 200 chunks to embed: text hits now, meaning: "indexing n of m", embedding continues in process'. None of this is implemented: SearchResult.meaning is only ever 'on'/'off' (search.ts:79); refreshIndex awaits every missing embed synchronously with no 200-chunk cap and no in-process continuation (index.ts:76-85,103); grep -rni 'indexing|200|progress|n of m' over src/advisor/search/ returns nothing. The test author folded it ('out of this task's named Success list ... not tested here') but named no covering test, earlier task or existing code; no deferral exists for spec advisor; tasks.md mentions this behaviour only in task 9's _Prompt, so no later task picks it up. Failure scenario: the first search over three real projects' spec stores + docs + waits (easily >200 chunks) blocks synchronously on embedding all of them, returning no text hits and no progress until done — the exact case D12 exists to prevent. Fix: implement the >200-pending-chunk path — return text hits immediately with meaning 'indexing n of m' and continue embedding in process — and add a test, or record a tracked deferral if descope is intended. (retro P6; methodology item 1 'promised but not delivered')
- **Task Requirement:** NFR Performance; design C6/D12

### INFO [hygiene]: Transient embedder outage wipes the whole cached index
- **File:** src/advisor/search/index.ts:119
- **Issue:** index.ts:119-120 sets model = embedder?.model ?? ''. When the embedder is briefly unavailable after a successful index, readIndex sees parsed.model !== '' and returns empty files, so the next search rewrites the project index with model='' and no vectors, discarding all cached vectors; a later successful search must re-embed the entire corpus. Not a Success-line item and the design does not mandate preserving the index across outages, but it concerns the same code path as the D12 fix above and is worth handling then.
- **Task Requirement:** design C6 (index files / model change)
