## Findings

### WARNING: actionEvents change emitter not implemented
- **File:** src/advisor/actions.ts:22
- **Issue:** Task 10's Task line and design C8's interface list both require an actionEvents ('change') emitter in actions.ts. grep -rn actionEvents src/ finds zero hits and the module has no EventEmitter. Task 12's prompt wires the hub to 'the store's change emitter' from the functions tasks 10-11 export, so the deliverable is undelivered and task 12 has nothing to subscribe to. No deferral records the omission.
- **Task Requirement:** Task line: implement ... and actionEvents per design C8; C8 interface list

### WARNING: Throwing executor leaves action stuck and writes no advisor.action row
- **File:** src/advisor/actions.ts:301
- **Issue:** confirmAction calls executor(action, deps) with no try/catch and writes the advisor.action row only after it returns (line 303). Design flow 6 ('lock busy, git error, unknown project') requires the action to go failed with the message AND still write its advisor.action row. withStoreLock throws on a busy lock (state.ts:558-561) and checkpoint's execFileSync git calls throw on any git error (ledger.ts:240-241), both reachable from execDeferral/execDecomposition, so a real failure propagates out of confirmAction with no event row and the action left in state 'confirmed'. Untested.
- **Task Requirement:** design Error Handling flow 6; Requirement 6 AC 5

### INFO: StagedAction shape diverges from the design Data Models
- **File:** src/advisor/actions.ts:23
- **Issue:** Design state union is 'staged'|'running'|'done'|'refused'|'failed'|'dismissed' with optional decided and outcome:{status,detail[]}. Impl uses 'staged'|'confirmed'|'dismissed'|'failed' (adds 'confirmed', drops 'running'/'done'/'refused') and omits decided/outcome. A successful confirm stays 'confirmed' with no terminal/outcome record; per-action outcome lives only in the event log.
- **Task Requirement:** Task: per the StagedAction shape (design Data Models)
