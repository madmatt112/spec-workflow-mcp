# Implementation Log: Task 9

**Summary:** Replaced the task 8 /deferrals stub with the real read-only Deferrals page (design C10 Deferrals, D15; Requirement 7 AC 2). New DeferralsPage reads the per-project deferrals payloads ShellProvider exposes (deferralsByProject), shows enabled projects only, one Group per project (testid group-<projectId>). Controls: status chips (deferred/resolved/superseded, multi-select toggle, empty=all, counts per status) via the Chips primitive, a SearchBox over title+id+originSpec, and a single Pager over the combined filtered record set (current page's rows grouped by project). Rows (testid deferral-row-<projectId>-<id>) show status badge, id, title, origin spec and updated date; selecting a row opens a right panel showing the whole record: status, id, project, origin spec and phase, created/updated/resolved dates, tags, revisit trigger, resolution, and the context/decision/revisit-criteria body texts. Selected record is re-derived from current data each render keyed projectId::id, so a deferrals-update push refreshes list and open panel with no reload; toggling a project off drops its group and clears a panel scoped to it. Wired DeferralsPage into App.tsx, removed DeferralsStub from stubs.tsx, added shell.deferrals.* keys to en.json only. No resolve/supersede/edit control; no new fetch (reuses the existing /api/projects/:id/deferrals route via ShellProvider).
