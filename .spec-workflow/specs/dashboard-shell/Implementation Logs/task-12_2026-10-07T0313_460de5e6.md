# Implementation Log: Task 12

**Summary:** Replaced the task 8 Specs stub with the real list-plus-panel Specs page (design C10 Specs, D9; Requirement 5). SpecsPage renders every spec of every enabled project grouped by project from ShellProvider.specRows, with rows testid `spec-row-<projectId>-<spec>` showing state, spec, phase, versions as `R4 D3 T2` (missing parts dropped), tasks done/total, PR numbers, deferral count, retro word and updated time; five state chips (live, in-progress, closed, deferred, not-started), a debounced search over spec name and a pager via the shared primitives. Selecting a row fetches the task-7 C8 route GET /api/shell/projects/:projectId/specs/:specName and shows order, depends text, a runs table (id/start/end/status/tokens), the phase table, deferral records and files; each file row has a Copy path action that writes the absolute path with navigator.clipboard.writeText and, when that is missing or rejects, shows the path in an auto-selected read-only field (D9). A 404 shows "spec not found". The panel re-fetches when the row's updated time moves so an open page refreshes within 5s; shell-specs pushes replace the list with no reload. Removed the stub (deleted stubs.tsx, its only remaining export) and wired SpecsPage into App.tsx. Added shell.specs.* keys to en.json only. Added the e2e Specs isolation test. Fixed a latent WS-proxy defect blocking the test: the vite /ws proxy forwarded the browser's Origin unchanged, which the dashboard CORS rejects for any frontend port other than the dashboard's own or the vite default 5173, 500ing the handshake; added changeOrigin plus a proxyReqWs Origin rewrite to the dashboard origin.
