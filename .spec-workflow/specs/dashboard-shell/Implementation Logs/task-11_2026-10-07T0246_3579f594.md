# Implementation Log: Task 11

**Summary:** Replaced the task 8 /runs and /runs/:projectId stubs with the real Runs list, run page and Launch card in the shell module (design C10 Runs and Launch card, D8, D11; Requirement 4). New harness.tsx helper copies callHarness from the legacy HarnessPage (direct fetch that keeps the non-ok body for 400/409/500 display), adds buildLaunchInput (the GET setup view defaults overlaid with the saved file's supervisorModel, worktree and roles; spec always the launchable; per-role object shaped as HarnessPage 211-226), and an OpErrorView that renders the 409 reason, 400 field/error or 500 step/detail. RunsPage lists NowModel.runs of enabled projects in Live (state live) and Ended (ended, stopped, exited) groups; each row shows project, spec, run id, state badge, phase and age, and selecting it navigates to /runs/:projectId. A Launch chip in the header opens one card per enabled project: launchable spec, saved setup in five summary lines (spec, supervisor, roles, worktree, gates), Launch and Edit setup. Launch posts buildLaunchInput to the existing POST launch route via callHarness and is disabled with the reason when there is no launchable spec (view.disabledReason), when a live run row exists, or when launches[projectId].state is running or stopping; a refusal shows via OpErrorView. Edit setup renders the harness form fields (supervisor model, model per role, provider for eligible roles, worktree, gates) as a table and saves through the existing PUT setup route, then refetches. RunPage holds the harness view for the route project only while mounted (D11), and renders from harness-model and harness-run-detail: the phase strip, open spawns with declared/actual model, elapsed, lastTool and a >15m idle badge, a task table (verdict and tdd from the task-review summary route polled every 5 s, taskMeta risk and fix rounds, status chips and pager), rounds and spawns as two collapsed tables, and tabbed Ledger/Activity/Process log each with a text filter and follow toggle; the panel shows run id, start, code root, worktree, headless, providers, tokens and launch pid, a Stop button on the existing stop route enabled only while running or stopping, and the saved setup (else defaults) as a collapsed table, with "no run for this project" and Stop disabled when there is no ledger. App.tsx routes /runs to RunsPage and /runs/:projectId to RunPage; the RunsStub and RunDetailStub were removed from stubs.tsx (SpecsStub stays for task 12). Added shell.runs.* keys to en.json only. No new route, launch field or launch behaviour; the legacy HarnessPage.tsx was not touched (task 13 deletes it).
