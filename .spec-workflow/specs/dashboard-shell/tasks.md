Document version: v1

Design components map to tasks as follows: C1 and C2 are task 1, C3 is task 2, C4 is task 3, C5 is task 4, C6 is task 5, C7 is task 6, C7 hub wiring and C8 are task 7, C9 is task 8, C10 is tasks 8 (Usage), 9 (Deferrals), 10 (Now), 11 (Runs) and 12 (Specs), C11 is tasks 8 and 13, the Testing Strategy end-to-end suite is task 14, C12 is task 15, and the invariants and operator evidence are task 16. No steering document exists, so the standards are those of `.spec-workflow/agent-rules.md`: server tests in `__tests__` next to the module, node 20 guaranteed fields only, and frontend changes checked by the dashboard build because root `tsc` and vitest exclude the frontend (tsconfig.json, vitest.config.ts). Expected verifier spend: tasks 1 to 6 add brand-new server modules (structural-red, high risk), and tasks 7 to 14 each change more than the 200-line risk threshold (src/core/gate-rules.ts:31), so plan for 14 verifier runs; tasks 15 and 16 are low risk.

Dependency order: tasks 1 to 7 are server-only and land first, so each frontend task reads merged server messages. Task 1 has no dependency; tasks 2, 3, 4 and 5 use the task 1 types and file cache; task 3 uses the task 2 waits; task 6 calls tasks 3 and 4; task 7 wires the task 6 feed into the hub and adds the route and push. Task 8 swaps the frontend shell with stub pages for Deferrals, Now, Runs and Specs; tasks 9, 10, 11 and 12 replace one stub each; task 13 deletes the legacy modules that task 8 leaves on disk with no importer; task 14 adds the end-to-end suite; tasks 15 and 16 depend on no code. Every task leaves `npx tsc --noEmit`, `npm test` and the dashboard build green, and task 8 keeps the worktree e2e suite green by editing `e2e/worktree-no-shared.spec.ts` in the same commit.

## Decisions taken in this document

- D1 — The run-detail message carries the detail or null when no spec resolves: options were omitting the message without a spec; chosen because the run page then clears a stale detail the same way the run-model message sends a null model.
- D2 — One task swaps the frontend shell with stub pages, and later tasks replace the stubs: options were building the pages unrouted first and swapping last; chosen because the dashboard build bundles only imported modules, so an unrouted page is never checked.
- D3 — The no-shared worktree suite is edited in step with the pages: options were rewriting it in the removal task; chosen so every task leaves that suite green.
- D4 — Frontend tasks carry no red-first test, and the new browser suite is integration coverage in its own task: options were a Playwright red test per frontend task; chosen because the frontend has no unit harness and each Playwright run starts two servers.
- D5 — The gear reads the version from the info route of the first registered project and opens the changelog without a project: options were a new global version route, or dropping the version; chosen because design D13 keeps the version and no route is added for it.
- D6 — The wait summary wording is free and tests assert kind, since and detail fields: options were pinning exact summary strings; chosen because the summary is display text and the detail is the contract.
- D7 — An exited wait whose record has no end time is timed from its launch time: options were dropping the wait; chosen because Requirement 2 AC 4 needs the wait and the fallback is rare.
- D8 — An ended run's list phase is the phase of its newest phase end: options were no phase; chosen because Requirement 4 AC 1 shows a phase on every run row.
- D9 — The pointer-matching rule is copied into the shell modules, not exported from the overview watch: options were exporting the private helpers; chosen because the invariant keeps the overview watch out of the diff (Requirement 8 AC 2).
- D10 — Server tasks land before every frontend task: options were interleaving server and page tasks; chosen so each page reads merged server messages.
- D11 — Locale keys go by a usage scan that keeps template-literal prefixes: options were removing keys by the deleted files' namespaces; chosen because a namespace can be shared by a kept component.
