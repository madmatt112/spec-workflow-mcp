## Decisions taken in this document

- D27 — How the worktree e2e suite keeps a seeded record alive: options were stubbing the socket in the page, an env switch on the server, or seeding as design says with no switch; chosen an env switch because that suite runs a real controller, which would fail a seeded record at once and could start a real unit from a wait record, and a socket stub would drop the design's seeding.
- D28 — How the frontend helper test loads its modules: options were a static import, adding file suffixes across the frontend, or a computed import; chosen a computed import because a static one fails the root type check and pulls the frontend into a program it is kept out of, and a probe passed both vitest and the type check.
- D29 — The standing ESLint Success check: options were listing it or leaving it out; chosen leaving it out because this repository has no ESLint binary, config or dependency, so the check would red every task.
- D30 — How the work splits: options were one task per design component or smaller tasks; chosen the coordinator, controller and script each in two tasks, so a test author meets one bounded behaviour set at a time.
- D31 — The harness doc's deploy text: options were a task here or the close-out; chosen the close-out because neither the entry nor the design names it, as the run-pause spec did.
- D32 — How the cancel test reaches the 30-second limit: options were a new interval option, a real wait, or the injected clock; chosen the injected clock because it adds no interface to a design that pinned one.
- D33 — A rejected stop during cancel: options were failing at once or polling on; chosen polling on because the unit may still be going, and the limit gives the same answer.
- D34 — The integration suite's routing: options were the test author or implementer-only; chosen implementer-only because every criterion holds once earlier tasks land, so no red test can exist.
